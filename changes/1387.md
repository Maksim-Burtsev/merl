### Fixed

- `d` in C++ and C on a member of a name bound again on the same line (in a block, a range-`for`, a lambda, an `if` init statement, a `catch`) now reads the binding that holds the cursor, no longer the last one on the line (#1387)
- `d` in C++ and C on a member of a name declared without a value in a `for` or `if` init statement (`for (T x; ; )`, `if (T x; ok)`) or by a lambda's capture with no parameter list (`[x = T()] { … }`) lands on that binding's type, no longer on the outer namesake's (#1387)
- `d` in C++ and C on a member of a name declared by a macro defined in the same file (`DECL(T, x); x.get()`, with `#define DECL(T, n) T n`) offers a picker, no longer a jump to the outer namesake's type (#1387)
- `d` in C++ and C on a member of a name declared by a macro defined in an included header of the project offers a picker too, no longer a jump to the outer namesake's type (#1387)
