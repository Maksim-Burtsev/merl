### Fixed

- `d` on a method of a local bound to a literal or to a standard-library constructor (`out.append` after `var out = [Int]()`, `text.includes` after `const text = "a,b"`, `out.add` after `val out = mutableListOf<Int>()`) in Swift, TypeScript, JavaScript, Kotlin, C# and Dart says "no definition" instead of jumping to the project's only method of that name; a project extension of that name still answers (#1536)
- `d` in TypeScript and JavaScript on the name of a function expression (`return async function loader(…)`, `.map(function mapper(n) …)`) offers the project's namesakes as a declaration's own name does, instead of jumping to an unrelated object key of that name (#1536)
