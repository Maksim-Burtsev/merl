### Fixed

- `d` in Python, TypeScript and JavaScript, Java, Kotlin, Groovy, Scala, C#, Go and Dart on a word inside a string literal (`"t.rate()"`, a text block, a raw or verbatim string, a template literal's text) no longer jumps through the type of the name before the dot: it answers as on any word in a string; inside an interpolation (`f"{t.rate()}"`, `` `${t.rate()}` ``, `$"{t.Rate()}"`, `'${t.describe()}'`, `s"${t.rate()}"`) it still reads code (#1526)
- `d` in Python on a word of a string that is a whole dotted path, as `@patch("pkg.mod.Class.method")` writes one, jumps again to the declaration that path names; a path that names nothing in the project says `no definition` (#1526)
