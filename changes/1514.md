### Fixed

- In Java and Kotlin, a local or a field named like a class in one file no longer turns `d` on that class's members in other files into a picker (#1514)
- In Java, `d` on a member reached through a field named like a class inside an anonymous subclass whose base declares that field (`new Dresser() { … Tureen.make().quaff() … }`) lands on the member of the field's type instead of a picker (#1514)
- In Java, `d` on a method called on a parameter whose written type is a class that an inherited field shares its name with (`void param(Tagine Tagine) { Tagine.simmer(); }`, `Consumer<Tagine> f = Tagine -> Tagine.simmer();` in a subclass of a class declaring `Cassole Tagine`) lands on the class's method instead of a picker (#1514)
