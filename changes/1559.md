### Fixed

- `d` in TypeScript and JavaScript on a keyword (`export`, `import`, `const`) or on a primitive type in a type annotation (`moduleName?: string`) says `no definition` instead of jumping to the project's only member of that name (#1559)
- `d` in Rust on `Vec`, `String`, `Box`, `Option`, `Result`, `Some`, `None`, `Ok` or `Err` that the file neither declares nor imports lands on the standard library's definition, and on a primitive type (`usize`, `str`) on its documentation in `core`, instead of on a project item of that name such as a vendored `struct Vec` (#1559)
