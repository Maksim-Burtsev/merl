### Fixed

- `d` in TypeScript and JavaScript on a keyword (`export`, `import`, `const`) or on a primitive type in a type annotation (`moduleName?: string`) says `no definition` instead of jumping to the project's only member of that name (#1559)
- `d` in Rust on `Vec`, `String`, `Box`, `Option` or `Result` that the file neither declares nor imports lands on the standard library's definition, and on a primitive type (`usize`, `str`) on its documentation in `core`, instead of on a project item of that name such as a vendored `struct Vec` (#1559)
- `d` in C++ on a member of an `auto` local built by a standard container's constructor (`auto seen = std::vector<int>(); seen.push_back(p)`) answers it as a standard library member, as for a declared `std::vector<int>`, instead of jumping to the project's only method of that name (#1559)
- `d` in TypeScript on a member of a local built by a call of an import that is not installed (`const jitiLoader = createJiti(""); jitiLoader.import(p)`) says `no definition` instead of jumping to the project's only member of that name (#1559)
