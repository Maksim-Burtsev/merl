### Fixed

- `d` in Ruby on a method of an ActiveRecord model that `Model.find` returned (`@account = Account.find(id)` set once in the class, or a parameterless method ending in `@account ||= Account.find(id)`) lands on the model's method instead of offering every namesake (#1340)
- `d` in Ruby on a method of what another method returns, when that method ends in a call chain (`Webfinger.new(uri).perform`, or `@resource ||= Webfinger.new(uri).perform` with the ivar set nowhere else) and its `rescue` clauses only raise or give `nil`, lands on the returned class's method instead of offering every namesake (#1340)
- `d` in Ruby on a method of a method parameter whose YARD tag names one class (`# @param [Account] account` above `def call(account)`), read directly or through an `@account = account` set once in the class, lands on that class's method instead of offering every namesake; a `*`, `**` or `&` parameter, and one the method assigns again, binds in a pattern or a lambda, keep today's answer (#1340)
- `d` in Ruby no longer jumps to the first type of a name bound again before the use (a block parameter, `rescue => x`, a pattern, a multiple assignment, a second statement on the line, a nested `def`, an `@ivar` set in a multiple assignment or by `instance_variable_set`, or a parameter assigned in a branch): it offers every namesake instead (#1340)
- `d` in Ruby on a name used after a block closed earlier on the same line, whose parameter has the same name (`items.each { |entry| entry.lstrip }; entry.reconcile`), lands on the outer name's method again instead of offering every namesake (#1340)
