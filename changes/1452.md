### Fixed

- `d` on a name a Python, PHP or Dart file imports from a package that is not installed (`import pytest` with no pytest on disk, `use Symfony\…\Route;` with no `vendor/`, a `package:` import missing from the pub cache) lands on the import line, `via import X (not installed)`, as in TypeScript, instead of on a project namesake the file never imports (a Python name the file binds again, as in `try: from ujson import loads` / `except ImportError:`, and a package the project maps with `package_dir`, a local `venv/` or conda env or an editable install holds keep their answer); a Dart `@override` or `@deprecated` no longer jumps to a project function of that name, and a Dart annotation such as `@Route('/home')` lands on the class instead of a picker of the class and its constructor (#1452)
- `d` on a Java `java.lang` annotation (`@Override`, `@Deprecated`, `@SuppressWarnings`, …) no longer jumps to a project namesake in a package the file neither is in nor imports; on a Swift attribute (`@available`, `@escaping`, `@discardableResult`, `@MainActor`, `@Published`, …) it lands only on a type (a property wrapper, result builder or global actor), never on a `func`, and not on one in a SwiftPM module the file does not import; and on a named element of a Java annotation (`@Audited(level = 5)`) it lands on the element `int level()` of the `@interface` (#1452)
- `d` on a C# attribute (`[Authorize]`, `[Obsolete]`, …) or a `new X()` no longer jumps to a project type of that name in a namespace the file does not open (by a `using`, a `global using` or its own namespace); `[X]` also finds a project `XAttribute`, and a named argument `[X(Name = …)]` lands on that attribute's property (#1452)
