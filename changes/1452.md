### Fixed

- `d` on a name a Python, PHP or Dart file imports from a package that is not installed (`import pytest` with no pytest on disk, `use Symfony\…\Route;` with no `vendor/`, a `package:` import missing from the pub cache) lands on the import line, `via import X (not installed)`, as in TypeScript, instead of on a project namesake the file never imports (a Python name the file binds again, as in `try: from ujson import loads` / `except ImportError:`, and a package the project maps with `package_dir`, a local `venv/` or conda env or an editable install holds keep their answer); a Dart `@override` or `@deprecated` no longer jumps to a project function of that name, and a Dart annotation such as `@Route('/home')` lands on the class instead of a picker of the class and its constructor (#1452)
- `d` on a Java `java.lang` annotation (`@Override`, `@Deprecated`, `@SuppressWarnings`, …) no longer jumps to a project namesake in a package the file neither is in nor imports; on a Swift attribute (`@available`, `@escaping`, `@discardableResult`, `@MainActor`, `@Published`, …) it lands only on a type (a property wrapper, result builder or global actor), never on a `func`, and not on one in a module `Package.swift` declares that the file neither imports nor gets re-exported; and on a named element of a Java annotation (`@Audited(level = 5)`) it lands on the element `int level()` of the `@interface` (#1452)
- `d` on a C# attribute (`[Authorize]`, `[Obsolete]`, …) or a `new X()` no longer jumps to a project type of that name in a namespace the file does not open (by a `using`, a `global using`, a `<Using>` of the csproj or `Directory.Build.props`, or its own namespace); `[X]` also finds a project `XAttribute`, and a named argument `[X(Name = …)]` lands on that attribute's property (#1452)
- `d` on a Kotlin annotation the language imports itself (`@Deprecated`, `@Suppress`, `@JvmStatic`, `@Target`, …, also after `@file:` or `@get:`) no longer jumps to a project namesake in a package the file neither is in nor imports; and a C# file of several block namespaces, each with its own `using`s, now finds an attribute or a `new X()` only in the namespaces that block opens (#1452)
- `d` on a name a Python file imports from a package that is not installed, in an import wrapped in `( … )` over several lines, lands on that name's line of the import, `via import X (not installed)`, instead of on a project namesake the file never imports (#1452)
- `d` on a name a Python file imports from a package that is not installed, in an import continued with a backslash (`from steeplab import leaf, \` then `fixture` on the next line), lands on that name's line of the import instead of on a project namesake the file never imports; in Dart, a name two or more missing `package:` imports could give opens a picker of those import lines instead of jumping to a namesake the file does not import (#1452)
- `d` on a name of a plain Python `import` continued with a backslash (`import steepcan, \` then `steepjar` on the next line), from a package that is not installed, lands on that name's line of the import instead of saying "no definition"; a comment that ends in a backslash continues no import (#1452)
