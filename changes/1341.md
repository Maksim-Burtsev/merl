### Fixed

- `d` in Swift, from a test target, on a member its own target declares again with the same signature (`result.isFailure` where both the library and the tests extend `Result` with `var isFailure`) lands on the test target's one, which shadows the library's, instead of a picker of both; and on a member read without a call (`error.asAFError?.reason`) where a property and a method share the name, it lands on the property instead of a picker with the method (#1341)
- `d` in Swift on a key path handed to a generic wrapper's method that takes a closure of the wrapped value (`mutableState.read(\.eventMonitor)` on a `Protected<MutableState>`) lands on the wrapped type's member instead of a picker of every namesake (#1341)
- `d` in Swift on a call of overloads that differ only by the type of an argument (`upload(stream, with: request)` where `stream` is an `InputStream` and the other `upload`s take `Data` or `URL`) lands on the one overload that takes it, when the argument is a literal, a value of a written type or a constructor call and the other overloads take structs of other names; a protocol, a generic or defaults still open a picker (#1341)
- `d` in Swift on such a call whose argument is a static call followed by a property (`session.upload(data, to: url)` with `let url = Endpoint.method(.post).url`) reads the argument's type from the static func's written return type and the property's written type, so it lands on the overload that takes it; a generic return, an optional chain or a generic property still open a picker (#1341)
- `d` in Swift on a call of such overloads where one takes an array or an alias of one (`serialize(component, forKey: keyPath)` against `serialize(_: URLEncodedFormComponent, ..)`, `serialize(_: URLEncodedFormComponent.Object, ..)` and `serialize(_: [URLEncodedFormComponent], ..)`) rules out the array ones for a value of a project type, and reads the type of the element in `array.enumerated().map { index, component in` as it does in a `for (index, component) in array.enumerated()` loop, so it lands on the one overload that takes it (#1341)
- `d` in Swift on a method a class gets from a default implementation in a constrained protocol extension (`serializer.serializeDownload(..)` on a `JSONResponseSerializer`, a `ResponseSerializer`, which refines `DataResponseSerializerProtocol & DownloadResponseSerializerProtocol`, served by `extension DownloadResponseSerializerProtocol where Self: DataResponseSerializerProtocol`) lands on that implementation instead of a picker of every namesake: the class's protocols are followed through the protocols they refine, and an extension bounded by `where Self: P` counts when the class conforms to every `P`; any other `where` clause still leaves it to the picker (#1341)
- `d` in Swift on a member at the end of a chain of calls that starts with a value (`session.download(.get).serializingDecodable(TestResponse.self).response`) follows each call's written return type, a generic one such as `DownloadTask<Value>` included, and lands on that type's member instead of a picker of every namesake; when an `if let`, a `for`, a `case let`, a closure's or a nested func's parameter or a block's `let` of the same name sits between the value's binding and the call, it keeps the picker. A call whose written return type is a generic parameter (`func held<T>(_ t: T) -> T`, the parameter list spread over lines, or one of the enclosing type's, an extension's included) no longer counts as returning a project type of that name, and a closure's parameter (`others.map { w in w.sift(1).scoops }`) is typed by the closure the cursor is in, not by another closure on the line or an earlier `w` of the same name; all of these opened the wrong member before (#1341)
- `d` in Swift on an argument label inside an implicit `.init(` handed to a type's call (`AuthenticationInterceptor(…, refreshWindow: .init(interval: 30, maximumAttempts: 1))`) lands on the parameter of the type the outer callee's parameter of that label names (`RefreshWindow`'s `init`) instead of finding nothing; a call on a value, overloads, a generic, an alias or a type declared more than once still find nothing (#1341)
- `d` in Swift on an implicit member passed to a method of a value (`kite.fly(.squall)`) whose name a closure parameter, an `if let`, a `case let`, a `for` or a nested func's parameter rebinds earlier on the same line (`{ (kite: Buoy) in kite.fly(.squall) }`, `for kite in buoys { kite.fly(.squall) }`) opens a picker that holds the answer instead of jumping to the case of the outer value's type (#1341)
- `d` in Swift on a method of a value rebound earlier on the same line by a `let` or `guard let` statement (`do { let torch = Ember(); torch.flare() }`, `guard let torch = maybe else { return }; torch.flare()`), or written as a projected value (`$glim.flare()` on a property wrapper whose `projectedValue` is another type), opens a picker that holds the right method instead of jumping to the method of the outer value's type (#1341)
- `d` in Swift on a member of an enum payload bound by a pattern (`if case let .multipartEncodingFailed(reason) = self, reason.isBodyPartInputStreamCreationFailed`, `guard case let .held(x) = m`, `if case .held(let x) = m`) lands on the member of the payload's type written in the enum's `case` instead of a picker of every namesake; an `else if case let … = reason` that reads the name it binds no longer jumps to the member of the outer `reason`'s type, and a generic enum, a payload of another arity, a second `case` or a rebinding later on the line still open a picker (#1341)
- `d` in Swift on a member of an enum payload bound by a `switch` arm (`switch mooring { case let .held(kite): kite.fly(.squall) }`, `case .snagged(let reason):` on a line of its own, `switch self` included) reads the subject from the arm's `switch` header and lands on the member of the payload's type written in the enum's `case` instead of a picker of every namesake; a later arm, a `where` clause, an arm of several patterns, a generic enum, a rebinding in the arm or a subject of the bound name still open a picker (#1341)
