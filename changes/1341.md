### Fixed

- `d` in Swift, from a test target, on a member its own target declares again with the same signature (`result.isFailure` where both the library and the tests extend `Result` with `var isFailure`) lands on the test target's one, which shadows the library's, instead of a picker of both; and on a member read without a call (`error.asAFError?.reason`) where a property and a method share the name, it lands on the property instead of a picker with the method (#1341)
- `d` in Swift on a key path handed to a generic wrapper's method that takes a closure of the wrapped value (`mutableState.read(\.eventMonitor)` on a `Protected<MutableState>`) lands on the wrapped type's member instead of a picker of every namesake (#1341)
- `d` in Swift on a call of overloads that differ only by the type of an argument (`upload(stream, with: request)` where `stream` is an `InputStream` and the other `upload`s take `Data` or `URL`) lands on the one overload that takes it, when the argument is a literal, a value of a written type or a constructor call and the other overloads take structs of other names; a protocol, a generic or defaults still open a picker (#1341)
- `d` in Swift on such a call whose argument is a static call followed by a property (`session.upload(data, to: url)` with `let url = Endpoint.method(.post).url`) reads the argument's type from the static func's written return type and the property's written type, so it lands on the overload that takes it; a generic return, an optional chain or a generic property still open a picker (#1341)
