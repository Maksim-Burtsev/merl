- `d` on a member after a cast lands on the cast's type: Java `((Cup) v).fill()` with a one-letter or twice-cast value, C# `((Cup)v).Fill()`, `(v as Cup).Fill()` and `(v as Cup)?.Fill()`; Kotlin `if (x !is Cup) return` types `x` as `Cup` below it, and a Java or Kotlin name checked or cast in another method, or in a Kotlin `if (x is T) { … }` / `when (x) { … }` block that closed above, keeps its declared type (#1494)
- `d` after more casts and checks lands on the written type: C# `g.Fill()` after `if (v is not Cup g) return;`, Java `x.size()` after a closed `if (x instanceof Cup) { … }` (the declared type), Kotlin `val z = (x as? Cup) ?: return`, Scala `v.asInstanceOf[Cup].fill()` and `val k = v.asInstanceOf[Cup]`, Dart `(v as Cup).fill()`, `(v as Cup?)?.fill()` and `final k = v as Cup;` (#1494)
- `d` in a Swift `switch` arm `case let e as Cup:` lands on `Cup`'s member for `e.fill()` (#1494)
- `d` on a Dart local or parameter checked with `is` lands on the checked type's member where Dart promotes it: inside `if (v is Cup) { … }` and below `if (v is! Cup) return;`, also when the exit is a wrapped `throw` (which jumped to the declared type before); a check of a type outside the declared one or an enclosing check, a value assigned again, or an `else` branch keep the declared type or the picker (#1494)
