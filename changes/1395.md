### Fixed

- `d` in Bash on a variable bound again earlier on the cursor's line (`for x in a b; do echo "$x"; done`, `read -r x; echo "$x"`, `x=1; echo "$x"`, a `local` in a one-line function) lands on that binding instead of an older assignment, a command named like a function no longer lands on a `local` variable of its name, and a `x=1 cmd` prefix, which sets `x` for that command only, no longer counts as an assignment for the lines below it (#1395)
