### Fixed

- `d` on a type parameter named like a type of the project (`class Box<Cup>` while `class Cup` exists) in C#, Rust, Go and C++ lands on the parameter inside its generic instead of on the project type (#1438)
- `d` on a member of a value whose type is a type parameter with no bound (`x.pour()` in `func f[T any](x T)`, `func f<T>(_ x: T)`, `fn f<T>(x: T)`) in Go, Swift and Rust no longer jumps to a project type's method of that name; in Go, a bound interface of the project (`[T Pourer]`) leads to its method (#1438)
- `d` on a member of a field typed by such a parameter (`held.pour()`, `self.held.pour()` inside `Rack<T>`) in Swift no longer jumps to a project type's method of that name (#1438)
- `d` on `self.held.pour()` inside `impl<T> Rack<T>`, where the struct has a field `held: T`, no longer jumps to a project type's method of that name in Rust (#1438)
- `d` on a method through a Go type parameter bound by an interface written on one line (`[T Pourer]` with `type Pourer interface{ Pour() }`) lands on the interface instead of offering every `Pour` of the project (#1438)
- `d` on a member of a value or field whose type is a C# type parameter with no `where` constraint (`x.Quaff()` in `void Sip<T>(T x)`, `held.Quaff()` / `this.held.Quaff()` inside `class Rack<T>`) no longer jumps to a project type's method of that name; a constrained one (`where T : Goblet`) still lands on the constraint's method, and so does an `override` or an explicit interface implementation, which inherits it unwritten (#1438)
- `d` on a member of a C# property or a field initialized by a call whose type is an unconstrained type parameter (`public T Held { get; set; }`, `T made = Make();`), or of a value typed by a variant parameter (`interface I<in T>`, `<out T>`), no longer jumps to a project type's method of that name (#1438)
- `d` on a member of a Go field typed by its struct's type parameter (`c.held.Clink()` with `c Cup[T]`) follows the type argument written at that position, so it lands on the bound's method (`[T Toaster]`), the concrete type's (`Cup[Goblet]`), or says "no definition" for an unbounded one, instead of jumping to a project type's method of that name; a method of an inline bound (`[T interface{ Clink() }]`) lands on that bound (#1438)
- `d` on `self.held.quaff()` in Rust no longer jumps to a project type's method of that name when the field is `&T` or `Box<T>`, or the impl is an `unsafe impl` (#1438)
