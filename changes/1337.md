### Fixed

- `d` in JavaScript and TypeScript on a default import now lands on the declaration the module exports as its default (`export { name as default }`, in a package or in the project, and `export default name` in a package's types) instead of saying no definition or offering every namesake (#1337)
- `d` in JavaScript and TypeScript on a name a `require` or `import` takes from a file inside a package (`require("redbean-node/dist/bean-model")`) now lands in that file's declarations, instead of offering a picker with the same name in other folders of the package and in the built `.js` beside it (#1337)
- `d` in JavaScript on the key of a renamed `require` (`autoStart` in `const { autoStart: start } = require("./cf")`) now lands on the module's export instead of saying there is no definition (#1337)
- `d` in JavaScript on a member a `require`d package declares twice, once in its ES-module copy (`dayjs/esm/index.d.ts`, `ws`'s `index.d.mts`), now lands in the copy `require` reads instead of offering both (#1337)
- `d` in JavaScript and TypeScript on a member of a named import that its module binds as `const name = new Class(…)` (`log.debug` with `export const log = new Logger()`) now lands on the method of that class instead of offering every `debug` in the project (#1337)
- `d` in JavaScript on a member of a value typed by a JSDoc `@typedef` that joins an object type with `&` (`/** @typedef {Result[] & { timings?: Record<string, number> }} Results */`, then `/** @type {Results} */ const results = []` and `results.timings`) now lands on that `@typedef` instead of offering every `timings` in the project (#1337)
