### Fixed

- `d` in JavaScript and TypeScript on a default import now lands on the declaration the module exports as its default (`export { name as default }`, in a package or in the project, and `export default name` in a package's types) instead of saying no definition or offering every namesake (#1337)
- `d` in JavaScript and TypeScript on a name a `require` or `import` takes from a file inside a package (`require("redbean-node/dist/bean-model")`) now lands in that file's declarations, instead of offering a picker with the same name in other folders of the package and in the built `.js` beside it (#1337)
- `d` in JavaScript on the key of a renamed `require` (`autoStart` in `const { autoStart: start } = require("./cf")`) now lands on the module's export instead of saying there is no definition (#1337)
- `d` in JavaScript on a member a `require`d package declares twice, once in its ES-module copy (`dayjs/esm/index.d.ts`, `ws`'s `index.d.mts`), now lands in the copy `require` reads instead of offering both (#1337)
- `d` in JavaScript and TypeScript on a member of a named import that its module binds as `const name = new Class(…)` (`log.debug` with `export const log = new Logger()`) now lands on the method of that class instead of offering every `debug` in the project (#1337)
- `d` in JavaScript on a member of a value typed by a JSDoc `@typedef` that joins an object type with `&` (`/** @typedef {Result[] & { timings?: Record<string, number> }} Results */`, then `/** @type {Results} */ const results = []` and `results.timings`) now lands on that `@typedef` instead of offering every `timings` in the project (#1337)
- `d` in Svelte, JavaScript and TypeScript on a component a package's entry re-exports as a default (`import { Button } from "@immich/ui"`, with `export { default as Button } from './components/Button/Button.svelte'`) now lands on its `declare const Button` in that file, instead of offering the `type Button = ReturnType<typeof Button>` beside it and every namesake component elsewhere in the package (#1337)
- `d` in JavaScript and TypeScript on a member of a name declared again earlier on the same line (`{ const { k } = box; k.pour(); }`, `const k = new Teapot(); return k.pour();`, `xs.map((t) => { const k = t; return k.pour(); })`) opens a picker that holds the answer instead of jumping to the member of an outer `k`'s type; and on a member of a name a `var` declares further down its function or inside one of its blocks (`if (on) { var k = new Teapot(); } return k.pour();`, a `var` after the use, in a `for`, a `try` or a `case`), it reads the `var` instead of an outer `k` of another type, which it jumped to before; a declaration in a block that closed before the use or opens after it, and a `var` below the use of a parameter or of a name already assigned above, keep the outer `k`'s answer (#1337)
- `d` in JavaScript and TypeScript on a member of a name a `var` of an outer function declares (`function inner() { return k.pour(); } var k = new Teapot();`, or a `var k` in an `if` above an arrow that reads it) now reads that `var` instead of jumping to the member of a module-level `k` of another type; a parameter or a declaration of the inner function's own keeps its answer (#1337)
- `d` in JavaScript on `node.parent` inside an ESLint rule's visitor (`ObjectPattern(node) { node.parent }`, `"Property:exit"(node)`) now lands on the `parent` that ESLint's `interface NodeParentExtension` declares, instead of a picker of every `parent` in the project; a `Program` visitor's node, which has no parent, keeps today's answer (#1337)
- `d` in JavaScript on a member of a value a function returns under a JSDoc `@returns` that joins types with `&` (`@returns {Required<VerifyOptions> & InternalOptions}`, then `const options = normalize(…)` and `options.filename`) now lands on the one side's `@property` that declares it, instead of offering every `filename` in the project; a member both sides declare keeps the picker (#1337)
- `d` in JavaScript and TypeScript on a member of what a method returns, when the method's object is itself read from a field (`const sourceCode = context.sourceCode; sourceCode.getScope(node).variables`, or `const scope = sourceCode.getScope(node); scope.variables`), now lands on the member of the return type the method declares instead of offering every `variables` in the project (#1337)
- `d` in JavaScript and TypeScript on a member of a callback's parameter over an array a type declares inside a namespace (`scope.variables.forEach(variable => { … variable.references`, with `namespace Scope { interface Scope { variables: Variable[] } }`) now lands on the member of the namespace's own element type, also when the arrow's body spans several lines or the arrow starts the line after the call's `(` (`sourceCode.ast.tokens.filter(` with `token =>` on the next line), instead of offering every `references` in the project (#1337)
- `d` in JavaScript and TypeScript on a member of a name a `while` takes from `pop()` or `shift()` of a local array (`const queue = [sourceCode.getScope(node)]; let scope; while ((scope = queue.pop())) { scope.childScopes`), and on a member of a loop or callback element of an array written with one element (`const roots = [getRoot()]; for (const root of roots) root.children`), now lands on the member of that element's type instead of offering every `childScopes` in the project; an array of several elements or a spread, or a name the loop's body writes before the use, keeps the picker (#1337)
