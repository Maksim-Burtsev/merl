### Fixed

- `d` in Rust follows a call of a local closure (`let m = |path: &str| gitignore.matched(path, false);` then `m("a").is_ignore()`) to the type its body returns, read from a written `-> T` or from a body that is one expression, so the method after the call lands on its one declaration instead of a picker; a closure whose body has statements, or whose result starts at one of its own parameters, still opens the picker (#1302)
- `d` in Rust on a variant brought by a glob over a dependency's enum (`use regex_syntax::hir::HirKind::*;` then `Capture(..)` in a `match`) opens that variant in the dependency, where it opened a picker of namesakes or jumped to a struct of the same name; a name the file also imports, or a glob over a module rather than an enum, keeps the answer it had (#1302)
- `d` in Rust on a variant reached through a crate of the workspace that hands another crate on (`use grep::printer::SummaryKind;`, where `grep` has `pub extern crate grep_printer as printer;`, then `SummaryKind::PathWithMatch`) opens that variant, where it said "no definition" (#1302)
- `d` in Rust on a path whose type a `use` inside a `mod tests` brings (`use grep_regex::RegexMatcher;` then `RegexMatcher::new(..)`) follows that `use` past a multi-line string the module holds at column 0, so it lands on the one `new` instead of a picker of every `new` (#1302)
- `d` in Rust follows a parameter typed by the trait's own associated type (`caps: &mut Self::Captures` in a default method of a trait declaring `type Captures: Captures;`) through that type's bound, so `caps.get(0)` lands on the bound trait's `get`, and `let m = caps.get(0).unwrap();` then `m.end` lands on the field of the type `get` returns, instead of a picker; the same chain on a parameter bound by a generic (`holes: &H` with `H: Holes`) is followed too, and an associated type with no bound, or `Self::X` inside an `impl`, still opens the picker (#1302)
- `d` in Rust inside a package's `tests/` folder reads it as Cargo does, a crate per root (`tests/suite.rs` with `mod util;`, a `tests/NAME/main.rs`, or a test file declared by no other), so `use crate::util::Matcher;` in a test file lands on the `Matcher` of that test crate instead of a picker of every `Matcher`; a module two roots declare still opens the picker (#1302)
- `d` in Rust on a method of a closure's parameter, where the closure is an argument of a project method (`matcher.captures_iter(b"a, b", &mut caps, |caps| { caps.get(0) })`), types the parameter by that method's `F: FnMut(&Self::Captures)` bound and the receiver's `impl` of the trait (`type Captures = RegexCaptures;`), so `get` lands on `RegexCaptures::get` instead of a picker; a closure that ends on the cursor's line, or whose parameter is written with a type, still opens the picker (#1302)
- `d` in Rust on a method reached through a `for` variable over a project iterator (`for ig in self.parents().take_while(|ig| ..)`, `Parents` having `impl Iterator for Parents { type Item = &Ignore; }`) types the variable by that `Item`, through std adapters that keep it (`filter`, `skip`, `take_while`, `rev`, ..) and with the loop's `{` on a line of its own, so `ig.inner.ignore_matcher.matched(..).map(..)` lands on the one `map` instead of a picker; an adapter the iterator declares itself, one that changes the item (`map`), or an iterator generic over its item still opens the picker (#1302)
