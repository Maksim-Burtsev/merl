### Fixed

- `d` on a method of a name bound by unpacking a call whose return type is written (Python `first, second = serve_two()` with `-> tuple[Platter, Saucepan]`, a TypeScript `const [plate, pan] = servePair()` with `: [Platter, Saucepan]`, Go's later results `_, pan := servePair()` with `(*Platter, *Saucepan)`), a Python `near, far = Platter(), Saucepan()` or a TypeScript `const [a, b]: [Platter, Saucepan]`, lands on the method of that position's type instead of a picker of every namesake (#1484)
- `d` on a method of a name taken out of an object whose type is a one-line `interface Kit { cup: Cup; mug: Mug }` or `type Kit = { … }` (a TypeScript `const { cup, mug } = makeKit()`, a parameter `({ cup, mug }: Kit)`, or `kit.mug`) lands on the method of that field's type instead of a picker of every namesake (#1484)
- `d` on a method of a name a Rust `let` takes out of a struct (`let Kit { crock, wok } = kit;`, `let Kit { wok: w, .. } = kit;`, `let Rack(front, back) = rack;`) lands on the method of that field's type instead of a picker of every namesake (#1484)
- `d` on a method of a name a Swift `let (crock, wok) = servePair()` or a C# `var (crock, wok) = ServePair()` takes out of a call whose tuple return is written (`-> (Crock, Wok)`, `(Crock, Wok)`), or a C# `var (crock, wok) = new Hamper()` over its one `Deconstruct(out Crock crock, out Wok wok)`, lands on the method of that position's type instead of a picker of every namesake (#1484)
- `d` on a method of a name a Scala `val (crock, wok) = servePair()` takes out of a call whose tuple return is written (`def servePair(): (Crock, Wok)`) lands on the method of that position's type instead of a picker of every namesake (#1484)
