### Fixed

- `d` on a member called on a Java lambda's parameter over a field declared `List<Cup>` (`cups.forEach(c -> c.fill())`, `this.cups.forEach(…)`, `cups.stream().map(…)`) lands on `Cup`'s member, as it did over a parameter or a local, also in a two-parameter comparator (`cups.sort((x, y) -> x.size() - y.size())`); a raw `List` still opens the picker, and a field `c` of another type never answers for the lambda's own `c` (#1488)
- `d` on a member called on a TypeScript callback's parameter over an array whose element type is written (`const cups: Cup[]`, `Array<Cup>`): `cups.map(c => c.slosh())`, `forEach(function (c) {…})`, `filter`, `find`, `some`, `every`, and both parameters of `sort((a, b) => …)` land on `Cup`'s member, also when an outer `c` of another type is in scope (#1488)
- `d` on a member called on a Python lambda's parameter over a `list[Cup]`: `map(lambda c: …, cups)`, `filter`, `sorted(cups, key=lambda c: …)`, `max` / `min` and `cups.sort(key=…)`, and a lambda assigned to a `Callable[[Cup], bool]`, lands on `Cup`'s member, also when an outer `c` holds another type (#1488)
- `d` on a member called on a TypeScript arrow's untyped parameter passed to a function of the same file that declares it (`function each(f: (c: Cup) => void)`, then `each(c => c.slosh())`) lands on `Cup`'s member, also inside a function body; a method of an object (`pots.each(c => …)`), a generic callee, a callee passed around or shadowed by a parameter, and an arrow whose body declares the name again keep the picker (#1488)
- `d` on a member called on a Dart closure's untyped parameter over a list whose element type is written (`List<Cup> cups`, a field `final List<Cup> cups`): `cups.forEach((c) => c.fill())`, `map`, `where`, `any`, `firstWhere`, and both parameters of `sort((a, b) => …)` / `reduce` land on `Cup`'s member, also when an outer `c` holds another type; a raw `List` keeps the picker (#1488)
- `d` on a member called on a Go function literal's typed parameter (`each(cups, func(c *Cup) { c.Fill() })`) lands on `Cup.Fill` when an outer `c` of another type is in scope on the lines above (#1488)
- `d` on a member called on a C# lambda's parameter in `cups.Sort((a, b) => a.Size() - b.Size())` over a `List<Cup>` lands on `Cup`'s member for both parameters, and so does `Action<Cup> f = c => c.Fill();` written after a `{` or a `;` on the same line; a pair in another call (`Select((c, i) => …)`) keeps the picker (#1488)
- `d` on a member called on a Dart closure's untyped parameter passed to a top-level function of the same file that declares it (`void each(void Function(Cup) f)`, then `each((c) => c.fill())`) lands on `Cup`'s member; a call inside a class, a callee shadowed by a parameter or a local function keep the picker (#1488)
- `d` in a Swift method written on one line (`func pour() { _ = cup.fill() }`, `cups.forEach { $0.fill() }`) types a property of the enclosing type again: every other property's declaration above it was read as a local that might rebind the name, so each such cursor opened the picker (#1488)
- `d` on a Swift name bound earlier on the same line, by a parameter of a method written on one line (`func pour(cup: Mug) { _ = cup }`) or a `guard let` before a `;` (`guard let cup = … else { return }; _ = cup`), lands on that line instead of a property of the same name (#1488)
- `d` on a member called on a Kotlin lambda's parameter passed as the trailing lambda of a method of the same class that declares its type (`fun each(f: (Cup) -> Unit)`, then `each { it.fill() }` or `each { c -> c.fill() }`) lands on `Cup`'s member; a generic callee, a callee shadowed by a parameter, a local function or an inner class's method of the same name, and a lambda nested in another keep the picker (#1488)
- `d` on a Kotlin lambda's parameter that the lambda's body declares again (`cups.forEach { c -> val c = Mug(); c.fill() }`) no longer lands on the collection's element type (#1488)
- `d` on a member called on a C# lambda's parameter passed to a method of the enclosing class that takes a single `Action<Cup>` or `Func<Cup, …>` (`void Each(Action<Cup> f)`, then `Each(c => c.Fill())` or `Each(c =>` with a block on the next lines) lands on `Cup`'s member; overloads, a generic method, a second parameter, a callee shadowed by a parameter or a local function, and a nested class's call to the outer method keep the picker (#1488)
- `d` on a member called on a Swift closure's named parameter over an array whose element type is written (`cups.forEach { c in … }`, `map`, `filter`, `first`, `(c) in`, both parameters of `sorted { a, b in … }`), on one line or over several, lands on `Cup`'s member; a closure whose body names the parameter again before the cursor, or nests another closure, keeps the picker; a parameter in parentheses passed to a method declaring `(Cup) -> Void` (`each { (c) in … }`) lands on `Cup`'s member too (#1488)
- `d` on a member called on Swift's `$1` in a comparator over an array whose element type is written (`cups.sorted { $0.size() < $1.size() }`, `sort`, `min` / `max`, with or without `(by:`) lands on `Cup`'s member for both `$0` and `$1`; `$1` in any other closure (`reduce`, `map`) keeps the picker (#1488)
- `d` on a member called on either parameter of a Kotlin comparator lambda over a collection whose element type is written (`cups.sortedWith { a, b -> a.size() - b.size() }`, `sortWith`, `maxWith`, `minWith`) lands on `Cup`'s member; two parameters on any other call (`byName.forEach { k, v -> … }`) and a parameter the body declares again keep the picker (#1488)
