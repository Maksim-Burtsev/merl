### Fixed

- `d` on a member of an awaited TypeScript call declared to return `Promise<T>` (`(await shop.find()).boil()`, or `const k = await shop.find()` then `k.boil()`) lands on `T`'s member instead of a picker of every namesake, and a method declared to return `this` right after a typed variable (`kettle.size(2).named('a').boil()`) keeps the variable's type; an un-awaited call, and an `any` or undeclared return, still open the picker (#1469)
- `d` on a member at the end of a call chain headed by a static or companion factory (`Kettle.builder().size(2).build().boil()` in Java, Kotlin, C# and Dart) follows each link's declared return type and lands on that type's member instead of a picker of every namesake, and in TypeScript a chain of calls with declared returns (`shop.counter().kettle().boil()`, `Kettle.builder().size(2).build()`) keeps its type past the first call; a link with no declared return still opens the picker (#1469)
- `d` on a member after a TypeScript method declared to return `this`, past the first call of a chain (`new Kettle().size(2).named('a').boil()`), keeps the receiver's own type, a subclass's included, and in Swift a chain from a static factory (`Kettle.builder().size(2).build().boil()`, wrapped or on one line) follows each link's declared return even where a link's name sits on several types (#1469)
- `d` on a member past a Rust `.await` in a chain (`shop.find().await?.boil()`, where `find` is an `async fn` declared to return `Result<Kettle, _>`) and past a Python method declared `-> Self` (`Kettle().size(2).named("a").boil()`) lands on that type's member instead of a picker of every namesake; a plain `fn` returning a future still opens the picker (#1469)
- `d` on a member of a Python dict indexed by a key (`by_name["a"].boil()`, `by_name: dict[str, Kettle]`, a `Mapping` or `defaultdict` too) lands on the value type's member instead of a picker of every namesake; a loop over the dict itself (its keys) still opens the picker (#1469)
- `d` on a member of a TypeScript `Record<K, V>` indexed by a key (`by_name['a'].boil()`) and of a Java `Map<K, V>` read with `.get(k)` (`by_name.get("a").boil()`) lands on the value type's member instead of a picker of every namesake; a value type that is not a plain name, or a project class named like the container, still opens the picker (#1469)
- `d` on a member of a Kotlin `Map<K, V>` read by key (`byName["a"]!!.boil()`, `byName["a"]?.boil()`, `byName.getValue("a").boil()`, `byName.get("a")!!.boil()`), of a C# `Dictionary<K, V>` indexed by a key (`byName["a"].Boil()`, or `var j = byName["a"]` then `j.Boil()`), of a TypeScript `Map<K, V>` read with `.get(k)!` or `.get(k)?.` and of a Java `Map<K, V>` read with `.getOrDefault(k, d)` lands on the value type's member instead of a picker of every namesake; a value type that is not a plain name, or a project class named like the container, still opens the picker (#1469)
- `d` on a member of a Java `var` or a Dart `final` initialized from a static factory (`var b = Kettle.builder().size(2);` then `b.build()`, `final b = Kettle.builder();` then `b.size(2)`) follows each link's declared return and lands on that type's member instead of a picker of every namesake; a link with no declared return still opens the picker (#1469)
