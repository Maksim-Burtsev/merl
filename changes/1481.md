### Fixed

- `d` on a member called on what a generic base returns as its type parameter (`shelf.first().fill()` where `class Shelf extends Rack<Cup>` and `first()` returns `T`), in Java, Kotlin and C#, lands on `Cup`'s member instead of a picker of every namesake, a level further down too (`class Tall extends Shelf`), and in Java and C# from a bare call inside the subclass (`first().fill()`); a base written without arguments, an argument that is the subclass's own type parameter, or a method's own type parameter still open the picker (#1481)
- `d` on the same shape in TypeScript (`class Shelf extends Rack<Cup>`, also through `this.first()` and a field typed `T`) and Go (a struct embedding `Box[Cup]`, then `s.First().Fill()`, also through an embedded `*Shelf` and a `*Cup` argument) lands on `Cup`'s member; a base without arguments, the subclass's own type parameter and a method's own `<T>` still open the picker (#1481)
- `d` on the same shape in Swift (`class Shelf: Rack<Cup>`, then `shelf.first().fill()`, also through `self.first()`, a bare `first()` inside the subclass and `class Tall: Shelf`) lands on `Cup`'s member; a base without arguments, the subclass's own type parameter and a method's own `<T>` still open the picker (#1481)
- `d` on the same Swift shape through a method or a property declared in an `extension` of the base, or a stored property typed `T` (`shelf.load.fill()`), lands on `Cup`'s member; a property typed with a type parameter in an `extension` of a generic type no longer jumps to a project class that happens to share the parameter's name (#1481)
- `d` on a member of what a TypeScript method returns as a type parameter (`lid(): T` in `class Dish<T>`, or a method's own `<T>`) no longer jumps to a project class that happens to be named `T`; it opens the picker of every namesake (#1481)
- `d` on a member of what a bare call inside a Kotlin class's own function returns (`first().fill()` in `class Shelf : Rack<Cup>`, or any member function of the class or its bases) lands on the returned type's member; inside a lambda (`apply`, `with`, `run`), an extension function, an `object :` expression, a companion object, or beside a local function of that name it still opens the picker (#1481)
