### Fixed

- `d` on a member called on what a generic base returns as its type parameter (`shelf.first().fill()` where `class Shelf extends Rack<Cup>` and `first()` returns `T`), in Java, Kotlin and C#, lands on `Cup`'s member instead of a picker of every namesake, a level further down too (`class Tall extends Shelf`), and in Java and C# from a bare call inside the subclass (`first().fill()`); a base written without arguments, an argument that is the subclass's own type parameter, or a method's own type parameter still open the picker (#1481)
- `d` on the same shape in TypeScript (`class Shelf extends Rack<Cup>`, also through `this.first()` and a field typed `T`) and Go (a struct embedding `Box[Cup]`, then `s.First().Fill()`, also through an embedded `*Shelf` and a `*Cup` argument) lands on `Cup`'s member; a base without arguments, the subclass's own type parameter and a method's own `<T>` still open the picker (#1481)
