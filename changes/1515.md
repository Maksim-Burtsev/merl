### Fixed

- `d` on a method called on a local, a parameter or a field named exactly like a project class (Java `Pot Kettle; Kettle.boil()`, Kotlin `val Kettle = Pot(); Kettle.boil()`) lands on the method of the variable's type (`Pot.boil`) instead of the class's namesake or a picker, and in Rust a `let` or a parameter named like a struct with named fields (`let Kettle = Pot::make(); Kettle.boil()`) is the variable it is, so `d` on it lands on the `let` and its methods on `Pot`'s (#1515)
