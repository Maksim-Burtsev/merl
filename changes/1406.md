### Fixed

- `d` in TypeScript and JavaScript on a method of a value built from a class declared inside the function (`class Cup { … }` then `const y = new Cup(); y.pour()`, or `new Cup().pour()`) lands on that local class's method instead of the method of the class of the same name the file imports, and when a parameter or a `const` of that name hides the import, it offers a picker instead of jumping to the imported class (#1406)
- `d` in TypeScript and JavaScript on a method of a value built from a constructor function declared inside the function (`function Cup() { this.pour = … }` or `Cup.prototype.pour = …`, then `const y = new Cup(); y.pour()`) lands on that local method instead of the method of the class of the same name the file imports (#1406)
- `d` in TypeScript and JavaScript on a name, or a method of a value built from it, whose `function` declaration comes below the use in the same function (`const y = new Cup(); y.pour(); function Cup() { … }`) lands on that local function instead of the import of the same name, since JavaScript hoists function declarations to the top of their block (#1406)
