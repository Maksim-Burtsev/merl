### Fixed

- `d` in Rust on a method of a value bound by a nested tuple pattern (`let (kept, (dipper, _)) = (spoons, (Dipper, 1));`, or the same pattern over a call returning a nested tuple) lands on that value's method instead of a picker of every namesake, and a value built by a standard library associated call other than `new` / `from` (`String::from_utf8(b)?`, `String::from_utf16_lossy(w)`, `PathBuf::from(p).join("x")`) is typed by that function's declared return type, so its methods go into the toolchain's sources instead of a project method of the same name; inside a dependency's sources, a type its file imports from its own crate (`use self::look::Look;`) or reaches through a glob of its own modules (`use self::class::*;`, when the crate declares exactly one) is typed too, so a field of a value of that type lands on it (#1044)
