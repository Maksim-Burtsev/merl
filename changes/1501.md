### Fixed

- `d` on a member through `this` or a self alias lands on the right object: in Scala `self.count` under `class Outer { self =>` goes to `Outer`'s `count` from inside a nested class that declares its own; in TypeScript and JavaScript `this.size` in a method of an object literal (`const box = { size: 3, grow() { return this.size; } }`) goes to the literal's key instead of a class field of the same name; in C# `anon.count` after `var anon = new { count = 5 };` goes to the initializer; in Java and Kotlin `this.count` inside an anonymous class (`new Runnable() { int count; … }`, `object : Runnable { var count = 0 … }`) goes to its own field instead of a picker that lacks it (#1501)
