### Fixed

- `d` on a Go type declared inside a function or a block lands on that local type, not on a package-level type of the same name, and `d` on the parameter of a Java lambda after `return` lands on the parameter, not on a field of its name (#1470)
- `d` jumps straight to the one name in scope where it used to offer a picker with an out-of-scope namesake: a Go type switch's `n := o.(type)` over an outer `n`, a Python `case [value]:` capture over an earlier `value`, a Python module-level class or function over one defined inside another function, and a Ruby or Kotlin top-level function called from another top-level function over a class member of its name (#1470)
- `d` on a bare Kotlin call lands on the function of the file's own package when a namesake sits in a package the file does not import, and `d` on a call to a Scala `def` declared inside a method lands on that local `def`, not on an object member of its name, which it used to jump to or offer (#1470)
- `d` on a call to a Kotlin `fun` declared inside a function, made from that function's own body (a recursive call) or on the same line as its declaration, lands on that local `fun`, not on a class or object member of its name, which it used to jump to (#1470)
- `d` on a Go type declared in a grouped `type ( … )` inside a function lands on that local type, not on a package-level type of the same name (#1470)
- `d` on the name of a Go type declared inside a function lands on that declaration, and `d` on a field of such a local struct, in its keyed literal (`Damper{Draft: 2}`) or through a variable of it (`d.Draft`), lands on the local struct's field, not on the field of a package-level type of the same name (#1470)
- `d` on a key of a keyed literal of a Go type declared inside a function over another struct (`type Opts Config` or `type Opts = Config`, then `Opts{Name: "x"}`) lands on the field of that struct, where it used to offer every `Name` field by name (#1470)
- `d` on a field name in a Go anonymous struct written on one line (`[]struct{ Flue Flue }{}`) says "no definition" instead of jumping to a type of the same name (#1470)
