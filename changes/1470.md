### Fixed

- `d` on a Go type declared inside a function or a block lands on that local type, not on a package-level type of the same name, and `d` on the parameter of a Java lambda after `return` lands on the parameter, not on a field of its name (#1470)
- `d` jumps straight to the one name in scope where it used to offer a picker with an out-of-scope namesake: a Go type switch's `n := o.(type)` over an outer `n`, a Python `case [value]:` capture over an earlier `value`, a Python module-level class or function over one defined inside another function, and a Ruby or Kotlin top-level function called from another top-level function over a class member of its name (#1470)
- `d` on a bare Kotlin call lands on the function of the file's own package when a namesake sits in a package the file does not import, and `d` on a call to a Scala `def` declared inside a method lands on that local `def`, not on an object member of its name, which it used to jump to or offer (#1470)
