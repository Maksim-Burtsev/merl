### Fixed

- `d` in Solidity on a named argument's key (`Crate({heft: heft})`, `emit Counted({tally: tally})`, on one line or several) no longer jumps to the local or parameter of the same name: a struct's field is found by name, and an event's or function's parameter keeps a picker. On a name in its own declaration's initializer (`uint256 notch = notch + 1;`, `(uint256 a, uint256 notch) = (notch, 1);`, `for (uint256 i = i; …)`), `d` no longer answers with that line, where the name is not yet bound, but with the outer binding (#1397)
