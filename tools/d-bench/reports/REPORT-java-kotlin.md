## Top improvements

### 1. `d` in Java and Kotlin reads `import` lines: the project's package, or nothing
- For `Kind::Jvm`, `imports()` binds nothing. An imported class is searched project-wide, an imported JDK/Spring name gets project namesakes, and a package segment of an import line opens a picker of 21–97 locals.
- Resolve `import a.b.C;`, `import a.b.*;` and `import static a.b.C.m;`/`.*` to the files whose `package a.b` line matches (grep `^package`), then to `C.java`.
- A capitalised name with no import belongs to the own package, then `java.lang`.
- A package no project file declares → "no definition", with a status that names the import.
- On an import line: the class segment jumps to the class; a package segment says "no definition".

```java
// app/a/User.java
package app.a;
public class User {}
// app/b/Settings.java
package app.b;
public class Settings { public static class User {} }
// app/c/Use.java
package app.c;
import app.a.User;
class Use { String f(User user) { … } }      // d on User
```
Today: `User: by name, 2 declarations`. Want: a jump to `app/a/User.java` via the import.

### 2. `d` in Java: the method and the class around the cursor first
- Java has no `bindings()`. A parameter gets "no definition", and an own field or method comes in a picker with every local and `private` field of other files.
- Walk up by indentation: locals, lambda parameters, the method's parameters (wrapped down to `) {`), members one level inside each enclosing class (innermost first), then the class it `extends`.
- If nothing matches, search by name, dropping locals of other methods and `private` declarations of other files. When one of several candidates is left, offer it rather than jump.

```java
// app/b/Settings.java
public class Settings {
    private final Scheduler scheduler = null;
    private static String parentNameOf(String item) { return item; }
}
// app/c/Use.java
class Use {
    private final Scheduler scheduler = null;
    String f(VoteRequest vote) { scheduler.run(parentNameOf(vote.group())); … }   // d on scheduler, parentNameOf
    private static String parentNameOf(String item) { return item; }
}
// src/test/java/app/c/UseTest.java
class UseTest { Scheduler scheduler; }
```
Today: `scheduler: by name, 3 declarations` and `parentNameOf: by name, 2 declarations`. Want: `Use`'s own field and method.

### 3. `d` in Java: a Lombok accessor leads to its field
- In halo's main code, about 3,100 of 8,200 `get`/`is`/`set` call sites name no declared method but a field of a Lombok-annotated file. `d` answers "no definition" on all of them.
- Rule: a `getFoo(`/`isFoo(`/`setFoo(` (or `Type::getFoo`) with no method declaration leads to field `foo`, in a file that imports `lombok.`, where `@Data`/`@Value`/`@Getter` (or `@Setter` for `set`) sits on the class header or the field. Skip `static` fields.
- Jump only when the qualifier names the class (following `extends`: `CommentSpec::getCreationTime` → `BaseCommentSpec.creationTime`) or the receiver's declared type does. By name alone, offer the candidates.

```java
@Data public class User { private String title; }
class Use { String f(User user) { return user.getTitle(); } }   // d on getTitle
```
Today: `no definition for getTitle`. Want: `User.title (Lombok @Data)`.

### 4. `d` in Java: `Type::method` and `this::method` are qualified names
- `qualifier()` splits off the `::`, but `pathed` requires `dotted`, so `AuthProviderWithPriority::getName` gets 21 rows by name.
- For `Kind::Jvm`, read a `::` in front of the word like `.`. `qualified` already yields `AuthProviderServiceImpl.AuthProviderWithPriority.getName`, so the `Outer.find` filter picks it. `this::m` works like `this.m`.
- Kotlin shares this; its extension `fun Recv.m(` must qualify as `Recv.m`.

```java
class Use {
    void f(List<Inner> items) { items.stream().map(Inner::getName); }   // d on getName
    static class Inner { String getName() { return ""; } }
    static class Other { String getName() { return ""; } }
}
```
Today: `getName: by name, 2 declarations`. Want: a jump to `Inner.getName`.

### 5. `d` in Java: wrapped constructors and record components are declarations, and a call is never a variable
- Constructor rule: also accept `{mods+}{w}\s*\(\s*$` and `{mods+}{w}\s*\([^;)]*,\s*$`.
- A `Type name,` / `Type name)` line inside an open `record X(` declares the component and its accessor `name()`.
- On `name(`, keep only method and constructor candidates (today `values()` lists 7 `var values` locals).

```java

    public Rule() { this(null, null); }
    public Rule(
            String a,
            String b) {
    }
}
public record VoteRequest(
        String group,
        String name) {}
class Use { void f(VoteRequest vote) { new Rule("a", "b"); vote.group(); } }   // d on Rule, on group
```
Today: `Rule: by name, 2 declarations` (the class and the no-arg constructor), and `no definition for group`. Want: the 2-argument constructor, and `VoteRequest.group`.

**Also seen (not scored):** on an interface method's declaration (`Mono<User> disable(String username);` in `UserService`), `d` offers unrelated same-name methods (`AuthProviderService.disable`) instead of the implementations. - `fun PopulatedNewsResource.asExternalModel()` is qualified as a bare `asExternalModel`, so `PopulatedNewsResource::asExternalModel` lists all six extensions.
- Fix the `val|var` rule so `{w}` cannot be followed by `.`, and so the property name after `Recv.` is matched. Let `qualified` name an extension by its receiver. Read `::` like `.` (Java #4).

```kotlin
fun String.asExternalModel() = this

```

### 5. `d` in Kotlin: parameters and the enclosing class first (shares the scope walk with Java #2)
- Parameters have no rule: `idGetter(item)` → "no definition", and `searchQuery` → a picker without the parameter.
- A class's own method comes in a picker of 11 (`getTopics()`).
- Walk up to the enclosing `fun`: its parameters, lambda parameters, `for (x in`, and locals above. Then the enclosing class's members and constructor properties. Then search by name, with #1's drops.
